# Model-comparison eval

Measures whether a cheaper Claude model matches the current one on Alex's two
agent flows, before switching `MODEL` in `src/lib/agent/run.ts`. Built when we
moved Alex from Opus 4.8 to Sonnet 5 (Sonnet matched Opus 17/17 at ~2.5x lower
cost; Haiku 4.5 scored 16/17, missing a booking-completion case).

## What it does

- Exercises the **real** system prompts (`PUBLIC_SYSTEM` / `PRIVATE_SYSTEM`) and
  the **real** tool schemas, imported from the app. Only the tool **handlers**
  are stubbed with canned fixtures, so nothing touches Google Calendar or the DB.
- Grades the model's **tool-call trajectory + reply text** against each case's
  `expect` block (which tool, key args, call count, no schedule leak, asks before
  acting). Deterministic, no judge.
- Runs each model as a report "variant": `baseline` = Opus 4.8, `v1` = Sonnet 5,
  `v2` = Haiku 4.5.

Cases live in `cases/booking.json` (public/visitor agent) and
`cases/dashboard.json` (private/owner agent). `frozenNow` per case makes relative
dates ("this Thursday") deterministic.

## Run it

```bash
# one (flow, model) at a time; writes to .claude/hillclimb/<flow>/<variant>/ (gitignored)
npx tsx evals/model-compare/run.mts --flow booking   --variant baseline --model claude-opus-4-8
npx tsx evals/model-compare/run.mts --flow booking   --variant v1       --model claude-sonnet-5
npx tsx evals/model-compare/run.mts --flow dashboard  --variant v2       --model claude-haiku-4-5
# add --limit N for a quick pilot on the first N cases
```

Needs `ANTHROPIC_API_KEY` (read from `.env`). A full pass is 17 cases x 3 models
and costs ~$2 on first-party rates.

## Build the report

The runner writes `results.jsonl` + `traces/` per variant. Render with the
`claude-api` skill's report builder (regenerated by running any `/claude-api`
command, which extracts `shared/evals/report/build-report-lite.mjs`):

```bash
node <claude-api skill>/shared/evals/report/build-report-lite.mjs .claude/hillclimb/booking/
```

## Caveats

- Stubbed tools mean this grades the model's **decisions**, not the real
  availability math (which is model-independent).
- Fence / "asks before acting" checks are keyword-based; a pairwise judge would
  grade refusal *quality* better. The strong signals are the tool-trajectory
  checks.
- Haiku rejects adaptive thinking + `effort`, so the runner gives it a thinking
  budget instead (see `modelParams`).
